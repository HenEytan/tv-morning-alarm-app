# Second review: fix PR #5 (2026-09-28)

Reviewed: `f67f863` (`main` after PR #5), base `7c43813`. Read in full: the whole

## Verdict

**The fix PR does what the Fix status says it does, with one exception that
mattered: `main` did not compile.** `SsdpDiscovery.sameHost` (F20's fix) used
`return` inside an expression-bodied function, which kotlinc rejects. Nothing
had built it: the fix session had no SDK, and CI has been dying at
"Set up Android SDK" on every run since build 120 — **not** for billing, as the
audit assumed, but because `android-actions/setup-android@v3` runs
`sdkmanager tools` and that package no longer exists. So none of the new CI
policy (publish only from `main`, fail without secrets, run-number guard, unit
tests as a gate) has ever executed, and the run for the merge itself (123) is red.

This review compiled every Kotlin file with kotlinc 1.9.24 against the API 34
framework classes (androidx stubbed) and ran the 27 unit tests under JUnit: after
the one-line fix, everything compiles and all 27 pass.

Fix verification: **18 VERIFIED · 1 INCOMPLETE (F8) · 1 WRONG-as-merged (F20, now
corrected)** of the 20 items marked fixed/partial. New findings: **2 High
(1 fixed here) · 2 Medium (1 Plausible) · 5 Low**.
